## 3. 总体选择与兼容性

采用原有 facade → Host/Rooted → native backend 分层内的局部修复，不新建统一文件系统框架，不升级依赖，不改变默认 feature、MSRV 或公共方法签名。另两种方案均不采用：仅修文档无法解决 LF-01—LF-04；合并 Host/Rooted 发布与遍历后端会扩大权限、平台和失败恢复回归面。

本设计没有需要破坏公共签名的理由。可观察行为变化如下：

| 变化 | 受影响调用方与迁移 |
| --- | --- |
| Rooted 自我复制被更早拒绝 | 所有 Rooted tree copy 调用者；修正链接/目标布局，不依赖复制输出再次作为源 |
| Fail/Skip 保留并发新建目标 | 直接调用者和 `rs-fs-local`；Overwrite 仍按原策略，调用方不需改签名 |
| atomic 恢复的成功/错误和 durable 标志纠正 | 依赖旧错误结果的测试需更新；调用者按原 durability 契约处理 |
| Windows 条件写 Required 在 open 返回 RequirementNotMet | 原先先写入、commit 才处理错误的调用者需同时处理 open 失败；不再期待必失败请求产生候选恢复文件 |
| Windows read-link/copy 返回等价实际目标 | 不能再依赖 PrintName 或 verbatim 前缀原样输出；若只需显示名称，不能将原来的错误解析结果当实际访问能力 |
| 恢复对象获得 Send/Sync | 能力增强，无下游签名迁移；不承诺 LocalConditionalWriter 或全部泛型参数自动具备同样能力 |
| 无缓存遍历遵循原生并发枚举语义 | 稳定目录输出保持一致；目录并发变化时不提供快照或全局 exactly-once，重开模式仍去除已见名称 |

`rs-fs-local` 是主要直接消费者，须验证 copy 策略、失败状态和 list 输出；`rs-mime` 的临时 staging 作为回归消费者；`rs-magika` 是经前两者间接使用，不当作新增直接 API 客户端。已有下游未见条件写真实用法，不能声称 LF-06 已解决其现存故障。

## 4. LF-01：Rooted 树复制不读取自身输出

在 `RootedCopyBackend` 保存本次复制最初的 authority-relative `destination_root: Path`。所有候选源目录，包括普通目录和跟随链接后的实际目录，先执行包含关系与活动祖先循环检查，再调用 `prepare_directory`、申请 reader 和进入 frame。

最小包含关系规则为 `destination_root.as_path().starts_with(actual_source.as_path())`，包含相等；使用 Path 分量比较，不使用字符串前缀。它与 Host 已有 `reject_destination_inside_source` 的方向一致。对根目录源按命名空间根处理。根源调用仍保留现有初始检查，避免先创建目标根。

拒绝返回 `InspectSource` 阶段及 InvalidInput 底层原因，经现有错误映射对外暴露；保留已发生的统计和副作用，不回滚此前成功的兄弟项。检查失败前不能为该危险子项创建目标目录。保留 `active_sources` 的普通祖先环检查；该修改不承诺抵御所有外部并发目录移动或挂载别名，也不改用诊断路径打开文件。

回归至少包括 source/link 指向目标根、指向包含目标的祖先、普通 `cycle -> .`，以及合法外部兄弟目录链接。测试设置有限 entries/depth 作为旧实现安全护栏，但必须断言命中包含关系原因、未创建危险层目标，而非仅断言预算耗尽。

## 5. LF-02：将冲突策略带到发布边界

保留现有目的项预检查、同文件检查和 type-conflict 处理。构建 `LocalAtomicWriteOptions` 时，非 Overwrite 的普通文件冲突策略选择 `.with_create_new()`，不允许 writer 的第二次检查把并发目标升级成可替换对象。Overwrite 保留原行为。

对 open 与 commit 两处的 AlreadyExists 处理分别检查：只有能证明没有发布本次内容、没有待处理 staging 清理错误且冲突策略确实允许跳过时，才增加一次 skipped 并返回成功；不得把其他阶段的 AlreadyExists、Published/Indeterminate 或附带清理失败的错误吞成 Skip。竞争项为不同类型时，按现有 `decide_copy_destination` 和 type-conflict 策略解释；不能因为文件策略为 Skip 就忽略显式的类型冲突 Fail。遇到无法证明可以安全跳过的类型替换竞争，保留结构化失败，不引入删除竞争者再重试的循环。

Fail 保留竞争者并返回结构化冲突；Skip 不计 files/bytes/overwritten，不冲销已经消耗的真实 I/O 预算。若之前已按用户 Replace 类型策略删除旧目标，后续失败仍保留原有部分副作用标记。

在 `file.rs` 的预检查之后、writer 初始化之前及 writer 初始化之后/commit 之前各加一个 feature-gated 一次性测试边界。复用现有字符串 selector/线程所有权机制，在保留的 Root 权限下创建竞争 sentinel，禁止通过诊断路径越权注入。测试不依赖 sleep 或调度概率，也不新增公共业务 API。

## 6. LF-03：恢复结果表达真实父目录同步状态

将共享内部 `recover_atomic_install_error` 增加 durability 输入，返回 `Result<bool, LocalAtomicWriteError>`，bool 表示本次父目录链是否实际同步成功。两个 writer 直接采用该结果，删除固定 `.map(|()| false)`；最终仍与原有 file_durable 做逻辑与。

| 已发布且恢复清理成功 | 父目录同步 | 结果 |
| --- | --- | --- |
| NotRequired | 不调用 | Ok(false) |
| Preferred | 成功/失败 | Ok(true)/Ok(false) |
| Required | 成功/失败 | Ok(true)/SyncParent 错误，仍明确已发布 |

未发布、staging indeterminate、持续清理失败均不能伪造恢复成功，沿用原有主要安装错误、清理错误和所有权处理。已经发布但清理仍失败时，NotRequired 不同步；Preferred/Required 可尝试同步并在已有失败中保留实际次要错误。不得把清理失败降级成成功。

新增“安装内 unlink 失败、恢复 cleanup 成功、sync 成功”的确定性故障组合，并沿用现有 sync-failure 组合。测试矩阵覆盖 Host/Rooted、三种 durability、清理成功/持续失败/身份不确定、同步成功/失败，验证调用次数、destination 字节、staging 存在性、typed state 和 durable。原有默认 NotRequired 却要求 sync 失败的测试预期要按新契约修正，不删除其清理/状态断言。

## 7. LF-04：Windows 链接按原生实际目标解析

`parse_symbolic_link_target` 仍保持私有 `io::Result<PathBuf>` 形式，只读取经过范围校验的 SubstituteName，并读取 offset 16 的 Flags；PrintName 不能参与实际解析或复制目标选择。相对链接保留相对目标；绝对链接将支持的 NT DOS/UNC 前缀转换为语义等价的原生路径，不能仅去掉前缀而把绝对目标降成相对目标。

Flags 与可支持的目标形式无法一致解释或含未知 flag 时返回 InvalidData；不支持的 NT device 命名空间返回 Unsupported，不猜测为 root-relative 路径。本轮不扩展 UNC Host 支持或新的 NT namespace。既有 verbatim round-trip 测试改为验证相对性与实际 referent 等价，只有确实属于公开契约的原样拼写才要求保留。

原始 reparse buffer 单元测试覆盖两名称不同、PrintName 为空、两个 offset 顺序变化、Flags、非法长度/偏移、绝对前缀。Windows 原生用例创建两个不同内容目标，验证 Rooted reader 和复制后链接都访问实际目标。原生结果与 parser 测试共同证明行为；缺符号链接权限必须记录跳过原因和已运行计数，不能把跳过当原生验证成功。权威依据：[Microsoft REPARSE_DATA_BUFFER](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_reparse_data_buffer)。

## 8. LF-05：打开条件 writer 前验证静态保证

沿用现有 Append、Content+CreateNew、symlink policy 验证顺序，在 resolver 和任何 backend 创建之前调用已有 `validate_write_options(options, self.capabilities(), OpenWriter)`；附加原始请求 path 和可无 I/O 获取的当前目录上下文。Rooted facade 的委托路径获得相同行为。

本项仅提前拒绝静态不支持的 Required durability，不顺带提前拒绝已文档化的全部 Content 平台限制，也不改变 Preferred 或运行时文件系统限制的处理阶段。Windows 普通 writer capability 已表示不支持目录 durable write，复用该事实，不新增 capability 标志。

更新旧的 Windows Required open-success/commit-failure 公共测试，改为断言 open 的 RequirementNotMet、原目标不变、create_parent 未创建父目录、目录清单无 candidate/container。内部 backend 的防御性提交失败测试可以保留，证明绕过 facade 也不会错误发布。相关指南与规范设计的中英说明同步为提前失败。

## 9. LF-06：恢复访问能力跨线程

内部 trait 改为 `RecoveryAccess: Debug + Send + Sync`，由具体字段自然推导；不添加 unsafe impl，不给带 RefCell 的整个 Namespace 强行声明 Sync。Unix/Windows EntryAccess 已持有独立 File、名称、路径和数值身份，不依赖 Namespace 的可变借用。Fake backend 的 Access 也须编译满足边界。

对 `LocalRecoveryFile`、`LocalConditionalCommitError`、`LocalConditionalWriteOutcome<Sha256>` 添加编译期断言，并测试 error 能转换为 `Box<dyn Error + Send + Sync>`。用 thread::spawn 返回已产生的恢复结果，跨线程打开并读取候选，再验证 Drop 不删除文件；不要求 writer 本身可以跨线程。无需引入 anyhow 依赖。

## 10. LF-07：按需保存遍历名称

两种 frame 将 `seen` 改为 `Option<HashSet<OsString>>`。仅在以下条件之一成立时启用：显式配置 max_seen_name_bytes；或遍历有下降可能、配置有限 max_open_directories 且 reopen_policy 为 Reopen。下降可能定义为 recursive 且 max_depth 未设置或大于 1。无缓存时直接消费原生 reader，不复制名称进集合；有缓存时保持现有去重行为。

显式 max_seen_name_bytes 继续使用旧的累积名称计量、零值和终止语义，不因没有缓存需要而变成无效选项；保持在同一 admission 边界检查 budgets/deadline。不得为了快路径放宽 Rooted 身份验证、目录循环检测或 deadline 检查。预算不在 frame 弹出时自动返还。

稳定目录输出与统计必须一致。并发目录修改没有快照或全局唯一枚举保证，省略集合不会新增这种保证；启用 Reopen 的场景依旧抑制重开产生的已见名称。将该区别写入双语指南及规范设计，不新增公共配置项。

用私有状态测试证明不需缓存时集合为 None，显式预算/重开时为 Some；公开测试证明有限句柄重开不重复、预算与错误策略不变。新增 Host/Rooted 宽目录非递归基准，固定 100/10,000 条目、相同名字长度，在同平台同配置比较分配字节与耗时。收益验收是消除逐名称持有量，耗时不设跨机器绝对阈值；若实际收益不成立，记录结果并局部修订，不能宣称性能提升。

## 11. LF-08：只整理恢复协议的自然职责

公开 `LocalConditionalCommitError` 的英文类型级 `# Examples` 演示：构造确定的条件冲突；先检查 publication/reason/stage；读取 candidate；用 into_recovery_files 转移所有权；原 error 消耗后仍能读取；丢弃句柄不删除文件。示例使用独占临时目录并在所有句柄关闭后清理自己的产物，不触碰用户目录。给结果、错误字段补语义说明，不能宣称 Indeterminate 可盲目重试。

Windows 内部仅抽出 `NativeReceiptError`、`PrivateEntryGuard`、`PrivateEntrySetupError` 到相邻的 `native_receipt_error.rs`、`private_entry_guard.rs`、`private_entry_setup_error.rs`，各自保持定义与 inherent impl。windows.rs 保留 backend/receipt 编排和模块声明；namespace.rs 保留 namespace 与其紧密关联类型，不因一类型一文件机械拆完整目录。只将 guard 使用所必需的字段访问改为窄访问器或父模块可见性，不扩大到 pub(crate)。

补充 namespace 权限与诊断路径区别、身份校验前提、guard armed/disarmed 转移、清理失败所有权、receipt Published/NotPublished/Indeterminate 判据及 backend 检查点含义。移动前后保持状态算法、Drop 次序、错误 source 链与 cfg 一致，使用现有状态/恢复测试验证，无新增生产能力。

## 12. LF-09、LF-10：测试与测量不能静默接受失败

### 12.1 生命周期 fuzz

环境准备仍可按原约定跳过，例如无法创建 scratch root；准备成功后，两个被测临时资源创建分支必须成功，不再 `.ok()`。使用局部 `require_created<T>(result: LocalResult<T>, kind: &str) -> T` 在失败时包含错误和资源种类地 panic。当前无被测创建阶段错误白名单；真实环境不足应明确作为失败诊断，而非静默完成。

只在创建成功后扣减模型 entries、更新 Owned 状态并放入 current。在现有 lifecycle_model_tests 的 support 单元测试中喂入 Unsupported/InvalidPath，证明会拒绝而非跳过；固定 opcode 序列分别执行文件和目录创建、写入、清理。仅测试模型新增断言，不添加业务 API 故障。

### 12.2 Criterion

`copy_budget_width` 的每个样本复用 `assert_copy_limit(result, Entry)`。`copy_tree_depth` 的 limited 分支逐样本验证 Depth；success 分支 expect 成功并核对 files=1。setup/fixture cleanup 继续位于计时区外；完整 payload 预检保留，不必每次重读文件干扰计时。

选择在计时闭包内执行廉价类别/统计断言，成本透明且远小于文件 I/O，不为此引入自定义计时框架。新的测量结果不能与此前可能吞错的历史结果直接宣称加速。宽目录 walker 基准沿用同一“每个样本执行主体且检查结果”原则。

## 13. 验证、交付与风险
