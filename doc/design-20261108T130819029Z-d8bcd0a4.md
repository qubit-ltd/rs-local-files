## RLF-001：证据文档与链接检查

选择恢复两个既有文件名的证据索引，而非批量删除验证边界或把历史通过陈述当作当前通过。索引至少记录协议、目标平台、源码 revision、命令、实际执行测试数、结果、日志位置、卷类型和账户权限；未取得的信息显式标记“未取得”。没有原始日志时，只记录现存文档的历史陈述及其不可复核限制，不能伪造成功日志。

检查 Git 历史和当前本地可用材料；如实施环境有已授权的只读 CI 查询能力，可查询对应原生日志。对比日志 revision 和实施基线。证据缺失时恢复索引仍可解决失效链接，但验证事项继续标记待验证。同步六份双语文档，保证已验证、历史陈述和待验证三类状态一致。可补充中文索引；最小方案不强制新增双语证据副本。

新增 `tests/documentation_links_tests.rs`，只检查六份读者文档及两个证据索引的内联 Markdown 相对文件链接：去掉 `#fragment`，跳过纯锚点与带 URI scheme 的链接，按 Markdown 所在目录解析文件，要求目标存在。检查失败列出来源文件、行号及目标。当前输入格式为普通内联链接，可用无新增依赖的小型扫描器；明确不声称覆盖 reference-style Markdown、HTML 或锚点有效性。若新增文档采用其他语法，扩充检查器和对应 fixture。用有效相对路径、纯锚点、外部 URL、缺失文件四类样例验证扫描器。

## RLF-002：最小单缓冲区优化

保留所有 trait 实现、后端及公共签名。仅在两个固有方法增加 `if let [buffer] = buffers` 分支，栈上构造一个借用切片描述符，再调用原有 `Input::read_vectored` 或 `Output::write_vectored`。

读入口保留当前“所有缓冲区为空则 Ok(0)”的提前返回。写入口必须先执行现有 Open/failure_state 检查，避免终止 writer 的空请求从 BrokenPipe 变为成功。单元素空写仍交由原 Output 实现判定；不引入 write_all/read_exact，不改变字节计数、短传输、故障注入及 Windows fallback。多个缓冲区继续走现有 Vec 路径，避免扩大优化范围。`src/vectored.rs` 无须结构调整。

同步 reader Rustdoc：分配描述改为多缓冲区适配路径；说明单缓冲区不分配适配描述符，不承诺后端绝对零分配。writer 若说明分配行为也采用相同边界。不改变 qubit-io 依赖，不添加 unsafe、SmallVec 或新公开类型。

备选是直接使用 std native vectored I/O，但会绕开已有 trait 中的故障注入、计数和状态处理，拒绝。通用小向量重构涉及更多代码及依赖，收益不足，拒绝。

## Windows 核查决策

优先复核现有 `windows_rooted_staging_cleanup_tests`、`review_windows_root_enumeration_tests`、`lf3_temp_tests` 和 sealed cleanup 契约；实际名称实施时以源码为准。记录精确用例与非零执行数，覆盖无默认特性及全部特性。能在当前原生 Windows 环境或授权 runner 执行时才补齐运行证据，Linux 零用例或交叉编译不代替原生验证。

如原生验证失败，先定位实现、测试或环境原因，再做满足原契约的最小修复并回归。需要时可修改 Rust 源码、测试和 workflow；不因本轮主要有文档修复就限制这些必要变更。无原生执行条件时交付明确的待验证清单，不宣称该项已经验证通过。

## 兼容性、验收与风险

本方案无破坏兼容性的必要性，既有下游无需迁移。单缓冲区不再可能因适配描述符分配失败，是优化后的预期差异；其他错误优先级保持。

验收：十处失效引用得到处理，链接回归检查通过；单缓冲区借用描述符在栈上构造，读写状态及内容契约测试通过；相同工具链、后端、fixture 下采样显示单缓冲区固有入口适配分配减少，不以噪声吞吐差异作为正确性门槛；现有 CI、Rustdoc、coverage 门槛不降低。Windows 未取得的证据必须如实保留待验证状态。

实施允许为测试失败、ci-check.sh 错误或覆盖率不足新增或修改测试及必要源码，包括相关已有基线问题；区分基线问题和新增回归，记录原因，不通过删测试、扩大 ignore、放宽阈值绕过门禁。当前方案不报告任何实施验证结果。
