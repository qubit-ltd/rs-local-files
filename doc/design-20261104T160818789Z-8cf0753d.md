## 阶段与授权

当前方案生成阶段仅创建指定设计和实施计划；两份文档完成即结束本阶段，不执行代码修改、测试、暂存、提交或推送。此边界只适用于方案生成阶段。

## 最小方案及取舍

采用三个局部工作单元，不改 Host／Rooted 架构、发布协议或公共类型。比较过：

1. 只补文档：无法消除 RLF-001 的契约不一致，也不能回答 RLF-002 的收益问题，不采用。
2. 显式修复谓词、补齐契约、先测量再作有限优化：改动可独立验收，采用。
3. 统一重写向量接口或新增通用缓冲框架：扩大调用方迁移和生命周期风险，缺乏收益证据，不采用。

保留 Rust 1.94.0、edition 2024 和现有依赖，无新增生产依赖。公共 API 和正常成功行为保持兼容，无需下游迁移。

## RLF-001：让比较函数独立满足契约

当前 `before.identity() != after.identity()` 将 None/None 视为相等，而 Rustdoc 要求 identity 必须可用。将身份判定收紧为：两者均为 Some 且相等才继续；任何一侧缺失或不同立即返回 false。后续长度、字节计数和原生时间戳比较保持原样。

不增加文件系统查询，不把时间戳相等宣称为原子快照，不把 identity 当作内容版本。公开入口继续使用 Required observation。修复的意义是使内部 helper 自包含，避免未来复用依赖隐含前置条件，而非宣称已经修复可公开触发的数据损坏。

测试使用正常 Required observation 取得基准，再用 crate-private `LocalFileObservation::from_parts` 构造派生输入；不增加公共构造器。覆盖正常相等、双方缺失身份、任一方缺失、身份不同、缺失原生详情、长度不等、实际读取计数不符、修改时间变化及状态变化时间变化。时间戳测试用已有原生详情构造方法制作确定性值，不依赖睡眠或真实文件系统时间精度。Unix 与 Windows 分别覆盖各自 native_match 分支。

## RLF-002：测量门槛与有限优化

### 基准设计

在现有 Criterion target 注册 `vectored_io` 组，矩阵包含 buffer 数 0、1、2、8、16、64，以及每段 64 字节与 4096 字节。读接口比较固有 IoSliceMut 接口与直接 `Input::read_vectored`；写接口比较固有 IoSlice 接口与直接 `Output::write_vectored`。两者使用等价的打开文件、数据和起始偏移，夹具准备、打开、seek/reset、提交与清理在计时外；短读写按返回进度校验，不假定一次调用填满全部数据。

用 bench 专用模块测量适配转换，区分转换成本与系统调用成本。若需要复用私有转换，可在 bench 以受限路径模块加载 `src/vectored.rs`，只用于性能测量，不复制生产实现、不开放生产 API；遵守实施时实际规范，不能用该路径加载方式绕过测试源码规则。也可只采用公共端到端对照加独立分配采样，避免路径加载。默认采用后者。

基准报告记录 commit、Rust 版本、OS、CPU、文件系统、样本参数、置信区间和完整命令。保留相同机器相同工作负载的前后数据；不同主机结果不能直接作提升比例。分配计数采用 bench 专用采样，计数窗口仅包围一次适配调用，避免并发活动与 fixture 计入；不引入生产全局 allocator。

### 决策规则

基准是必交付物，优化是条件交付物。先完成基线，再决定：若 1～8 buffers 的调用在重复测量中表现出稳定收益空间，尝试安全 Rust 单缓冲快路径；多缓冲保持 Vec 转换。单缓冲直接构造一个借用 slice 的栈数组转发到现有 Input／Output 方法，不改变原生错误处理和 writer 状态机，不新增 unsafe。

候选仅在两轮独立运行中，小 buffer 工作负载的吞吐或延迟改善至少 5%、Criterion 95% 区间支持改进，且其余矩阵未出现可重复的超过 5% 退化时保留。数字是本轮工程决策门槛，不是 CI 时间断言。无可靠收益时保留生产实现，将 RLF-002 结论记为“完成测量，暂不优化”，附证据。不得把未测量称为完成，也不得为通过门槛降低样本量或删去退化场景。

若保留快路径，修改所有使用相同转换的固有方法，防止不同资源无依据地出现不同适配行为：reader、writer、temp file、Host atomic writer、Rooted atomic writer。只改已打开流的适配，不改 publish、abort 或 durability。

## RLF-003：就地明确契约

生产 Rustdoc 使用英文，报告及计划使用简体中文。补齐以下项目及适用章节：

- `byte_slices`／`byte_slices_mut`：保序、借用生命周期、可变借用互斥、仅分配描述符而不复制文件内容，分配失败映射为 OutOfMemory。
- `query_observation`：从同一保留句柄查询；Required 在无法提供所需事实时失败，Optional 允许缺失事实但不吞掉普通 I/O 错误；按 Unix／Windows／其他目标实际分支描述。
- `LocalFileReader::read_vectored`：空 buffers 不读文件，允许短读与 EOF、返回量是有序前缀，不保证填满所有 buffers；原生读错误及适配分配错误；Windows fallback 可能顺序读取多段，并在已有进度时返回进度而抑制后续错误。

Rustdoc 必须与最终性能分支一致：若保留单缓冲快路径，分配说明限定于需要 Vec 的路径。只补相关说明和小型可编译示例，不为格式一致而全仓重写文档。

## 兼容性及下游

`rs-fs-local` 依赖 reader、writer、options、outcome、error 和临时资源；`rs-mime` 依赖临时文件创建、关闭与 cleanup；`rs-magika` 的 Cargo 清单存在本地依赖。方案不改这些公共签名、错误类型和所有权结构，预计无需改下游源码。实施时验证本地依赖解析确实使用当前 rs-local-files，不能以 registry 版本通过替代本地回归。

双语 README、用户指南和既有设计文档本轮未确认独立缺陷，故不安排重写。若测量后公开文档有关于无分配的矛盾声明，仅同步修正相关中英文段落；不夸大优化范围。

## 验收与风险

- RLF-001：缺失身份回归在旧实现失败、新实现通过；原有快照行为测试保持通过。
- RLF-002：必有可复现基准和明确保留／不保留优化结论；有优化时补充单缓冲、空缓冲、多缓冲、短读写、错误和 writer 状态回归。
- RLF-003：上述接口 Rustdoc 契约完整、示例可编译，文档无失效链接或新的过度保证。
- 集成：运行项目实际 ci-check.sh，不降低测试或覆盖率门槛；默认／all-features 测试及文档检查通过，跨平台行为有对应目标的执行证据。
- 风险：基准噪声可能误导决策；修改转发入口可能绕过 writer 状态检查；构造测试观测值可能不满足真实平台约束。分别以重复测量、保留现有状态机入口、使用明确的派生 fixture 和平台分支测试控制。

没有目标平台执行环境时，明确记录未验证项，不把交叉编译称为运行通过。实施结果应逐项回填 RLF 编号、命令、退出码和测量结论。
