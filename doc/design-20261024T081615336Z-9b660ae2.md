## 3. 设计选择与兼容性

选择保留 Host／Rooted 分层、公共 Options 和 outcome/error 类型，修正内部事实传递与操作顺序。没有必要引入新的文件系统抽象、统一平台后端、泛型事务框架、异步层或公共测试接口。

比较过三种方向：

1. **仅更改错误映射及文案**：改动最少，但不能消除权限窗口、临时资源遗漏和无效测试，不满足目标。
2. **局部补充事实、调整顺序、增加确定性回归**：采用。内部类型允许增字段或调整私有签名，公共 API 保持现状。
3. **统一重写复制与条件写状态机**：可能减少平台重复，但风险和迁移成本明显超出本轮收益，不采用。

本设计不要求破坏公共源码兼容性、不升级依赖、不更改 MSRV `1.94`、edition `2024`、默认 feature 集或 crate 版本。必要的行为变化是纠正错误的保证：曾经误报的 `Unchanged`、`AtomicExchange` 和 `Io` 将返回真实分类；权限准备失败会更早失败。不能为保持错误行为而保留旧结果。

主要调用方 `rs-fs-local`／`rs-fs-local-lock` 的 SPI 不需要签名迁移；它们应重新运行 outcome/error 映射合同。经它们使用本库的 `rs-mime`、`rs-magika` 只需验证现有集成。不得主动修改这些下游项目。调用者若依赖旧的错误分类或自行补根路径，需要移除补偿逻辑，并按返回的 typed state/reason 处理。失败状态不确定时不能盲目重试或删除恢复文件。

## 4. 路径错误与复制副作用

### 4.1 缺失路径的原生语义（RLF-01）

位置：`src/local/internal/path_operations/path_management.rs::canonicalize_existing_prefix`，公共可达链为 Host `copy_with_options` → 树复制 facade。

将“缺失绝对路径一定有普通文件名”的断言改为错误分支。普通名称继续进入 missing tail；如果缺失尾部不能提供 `file_name()`，先用原生 `canonicalize` 获取该输入的实际错误，无法给出原生错误时返回 `InvalidInput`。每轮必须能够向父目录推进，根组件无法推进时也返回错误，不能无限循环。

不把 `missing/..` 词法折叠为父目录；Unix 原生遍历要求先存在并访问 `missing`。存在目录或链接后的合法 `..` 必须维持既有行为。错误经现有 copy pipeline 映射为 `LocalCopyFailure`，发生在目标变更之前，状态为 `Unchanged`。

### 4.2 将目标变更事实与统计分开（RLF-02）

位置：`src/rooted/copy/{destination,symlink,file}.rs`、`src/rooted/root.rs`、`src/local/local_copy_dir_error.rs`、`src/outcome/local_copy_failure.rs`。

在内部 `LocalCopyDirError` 增加 `Option<LocalCopyFailureState>` 事实提示及 crate 内 getter/builder；默认 `None` 表示现有 stage/statistics 推断仍有效。保留 `into_parts()` 原签名，转换前先读取提示，避免无关拆包修改。禁止通过增加 files/directories/overwritten 来伪装旧目标删除，统计仍只表示已有定义的成功工作量。

为 Rooted copy 保留递归删除的 typed `LocalFileError`：在 Root 内增加仅供 crate 使用的 typed 删除入口，原有内部 `remove_tree` I/O 适配入口委托它。直接透传 `remove_directory_tree` 的 `PublicationIncomplete`，不要先转 `io::Error` 再靠文本猜测是否改变。已有测试故障和非目录检查保留。

| 已观察事实 | 对本次 copy 失败的处理 |
| --- | --- |
| 删除前失败，且此前未复制任何目标 | 可保持 `Unchanged` |
| typed 删除错误确认已删除子项 | 至少 `PartiallyPublished`，即使复制计数为零 |
| 删除旧文件/目录已成功，后续创建、打开 writer 或复制失败 | 至少 `PartiallyPublished` |
| 原生结果无法判断目标是否改变 | `Indeterminate`，不能降为 `Unchanged` |
| 完整内容已发布，仅同步失败 | 保留现有可证明的 `Published`，不被准备阶段提示误覆盖 |

提示表达整个操作已有副作用的保守下界；与先前复制结果合并时，不能让后续局部 `Unchanged` 覆盖此前改变，也不能让计数覆盖原生不确定性。具体合并为一个 crate 内纯函数，并对表中全部组合做表驱动测试。不要新增公共状态或公开 Root 方法。

回归必须覆盖：替换目录删除至少一个子项后失败；旧文件删除成功但目录创建失败；已有变更后 writer 打开失败；真正删除前失败仍可报告未变。通过删除回调/现有 test-support 故障边界确定发生顺序，不能依赖目录枚举顺序或 chmod 偶然失败。

## 5. Rooted 权限发布顺序（RLF-03）

位置：`src/rooted/copy/file.rs`、`src/local/local_root_atomic_writer.rs`，必要时局部复用 `rooted::Permissions` 转换。

在内部 writer 增加可选的 staging 权限覆盖值和 `pub(crate)` 设置方法，供复制调用；普通 open_writer 没有覆盖值，行为不变。复制请求保留权限时，将已观察到的源 `rooted::Permissions` 传入 writer；复制文件完成后不再对最终目标执行 `root.set_permissions`。

提交顺序固定为：

1. 打开并检查现有目标，维持现有身份约束。
2. 按原 metadata policy 保留目标其他元数据。
3. 若存在复制专用权限覆盖，在 staging handle 上施加源权限。
4. 同步 staging 文件的数据及最终元数据。
5. 再次验证目标身份，安装 staging，按原策略同步父目录。

不能只在 copy 代码中提前 chmod staging 而让随后 `PreserveExisting` 再覆盖它；也不简单改为 `UseStaging`，以免丢弃原来保留的 ACL/xattr 等元数据行为。Unix 用精确 mode，Windows 使用现有可移植只读语义，不扩大成源 ACL 完整复制功能。权限失败发生在发布前，保留原目标；若该复制此前已经删除冲突目标，必须与 RLF-02 的事实合并，不能误报未变。

目录本身的权限应用路径不作本轮重构，树复制的 Required 支持范围不扩大。测试以 staging 同步/安装检查点观测权限和目标内容，不靠高频线程抢读或掉电实验；`durable=true` 只声称所支持协议中最终选定权限已在文件同步之前设置，不声称物理硬件保证。

## 6. 条件写的路径和回执（RLF-05—RLF-07）

### 6.1 三种坐标各司其职

从 `local_file_system/conditional.rs` 已解析的结果，分别传递 authority-relative 路径、namespace-absolute 路径、可选物理诊断路径。贯穿 rooted conditional facade、backend dispatch、Unix/Windows 构造；不从物理路径猜公共坐标。

当前 facade 传入名为 `diagnostic` 的参数实际是 `resolved.namespace_absolute()`，不能仅沿用变量名就把它当作物理路径。应明确改名并传入独立的可选物理坐标；本实现没有可靠物理坐标的 Rooted 分支传 `None`。`open_rooted_parent` 如需一条错误显示路径，可以使用 namespace-absolute 作为显示上下文，但不能因此将其写入公共 `diagnostic_path()`。

Unix `Namespace::entry` 用 namespace-absolute 的 parent 拼接恢复名；`EntryAccess` 仍只用保留的 parent FD 和单个文件名授权访问。物理诊断路径存在时也应拼接恢复名，而不是复用原目标名；无法证明物理坐标时保持 `None`，不能把 namespace 路径冒充物理路径。

Host 已绑定绝对路径的行为保持。Windows 对应签名同步编译，但只在确有坐标问题时改实现。覆盖非根 PWD、绝对/相对目标、失败候选和成功后保留的 cleanup 资源。改变 PWD 后，公开恢复路径仍可交回同一实例，且恢复对象的 FD 访问继续有效。

### 6.2 成功结果使用实际 native receipt

在内部 `NativeAttempt` 增加 `publication_method: LocalWritePublicationMethod`。它表示此次尝试使用的协议，不表示发布成功；每个构造点必须填入，避免缺失字段时用静默 fallback 猜测。

- 不覆盖安装：按原生实现填写 `AtomicRename`。
- Unix 内容交换：填写 `AtomicExchange`。
- Windows Host `ReplaceFileW` 带备份替换：填写 `AtomicReplaceWithBackup`。
- 不支持的协议继续拒绝，不为了补 outcome 改变平台支持面。

通用提交状态机保留成功发布那一次 receipt 的方法，并传给最终 `LocalWriteOutcome`。不能根据 precondition 推断，也不能被后续 rollback receipt 覆盖。fake backend 支持选择方法，分别断言透传；Windows 原生公共测试验证 Host 路径。

### 6.3 无效状态分类

`LocalConditionalWriter::commit` 的拒绝分支使用 `LocalConditionalFailureReason::InvalidState`，保持 `Prepare`、`NotPublished` 和现有底层 kind。abort 后、不可恢复写错误后、abort 失败后分别验证；不改变 `Interrupted`／`WouldBlock` 的既有重试规则，也不允许在状态终止后继续写入。

## 7. 临时资源与遍历预算

### 7.1 Host 构造失败清理（RLF-08）

将 Host 的“创建 native entry”和“建立 LocalTempFile／Directory owner”视为同一构造事务。最小实现是在二者组合结果统一失败时执行现有 sandbox 清理，而不是只匹配 native create 的错误分支；File 参数必须先释放再清理，以兼容 Windows。

清理仅限本次创建的私有 sandbox，不扫描或删除 parent 其他内容，不扩大临时资源并发保证。保留原始创建/身份错误作为主要错误。如果清理失败，将 sandbox 的确切诊断位置附在既有错误上下文/源链中，不能伪装创建成功或隐藏残留。没有必要为此新增公共恢复类型。若组合错误需要类型，限于当前 internal 子树。

测试分别在文件身份和目录身份观察时注入失败，确认没有返回 owner、sandbox 已移除、parent 既有条目不变。额外验证清理失败时原始原因及残留位置仍可定位。身份故障只在 `test-support` 下启用。

### 7.2 协作期限与零深度（RLF-09、RLF-10）

Host `next_entry` 外循环与去重内循环在继续执行下一次原生目录读取前检查同一绝对 deadline。过期时返回一个 `TimedOut` 并使迭代终止，error policy 不能让期限错误变成无限重试。检查点保证不继续主动扫描；不会取消正在阻塞的系统调用。

零深度在完成原有 Options、起始条目类型和 authority 验证后返回空遍历，不读取子目录项，不插入 seen 名称，不申请子项 budget。Host 创建时已有的 read_dir 打开/权限错误语义保持；优化点是禁止枚举子项，不擅自改变 open 阶段和 lazy 阶段的错误时机。Rooted 同样保留现有 eager/lazy 验证边界，不将原来必须观察的错误静默吞掉。

通过现有测试故障机制增加局部扫描计数/进度检查点或在私有循环使用可脚本化读取器；不新增公共可变时钟。确定性测试让 deadline 在重复项扫描期间过期，证明下一项读取没有执行。零深度配合零 entries/name budget 仍成功为空，并直接断言枚举次数与 seen 增量为零。

## 8. 测试有效性（RLF-04、RLF-11、RLF-12）

Windows 只修两处 `Path` 导入 gate，保留跨平台用例，不通过禁用整个测试规避编译问题。

CWD 子进程 helper 接收完整测试名，使用 `module_path!()` 去除测试 crate 名前缀后拼函数名，不硬编码多层目录。父进程在独立临时目录创建 sentinel 路径传给 child；child 在场景断言完成后写 sentinel。父进程同时检查退出码和 sentinel，证明主体执行完成。不要把易变的 libtest 英文统计文本作为唯一判据。

安装故障矩阵逐行记录期望结果、typed state、目标字节、staging 状态及附加错误。`Indeterminate` 不表示磁盘内容必须未知：确定性故障下可以同时断言磁盘字节与 API 的保守状态。只有公共合同真的返回 writer 时才断言 retained writer，不能为测试扩大公共 API。

strace 测试先单独启动无被测操作的 trace 探针。只对明确的环境缺失/ptrace 权限不可用给出带原因的跳过；探针成功后，真实 copy/rename 子进程非零退出一律失败并输出 stderr。返回状态和期望系统调用均必须检查。

## 9. 文档与示例（RLF-13—RLF-15）

### 9.1 消费者示例不依赖本地同名 feature

现有 README/指南用 `# #[cfg(feature = "digest")]` 支持本 crate 默认 feature 的 doctest。Rustdoc 会隐藏 `# ` 行，而 GitHub 原始 Markdown 代码块仍显示这些行。因此不笼统宣称所有渲染方式都会空跑：问题是把库内 harness 上下文带进消费者，且没有独立执行消费者上下文。

保留库内隐藏 wrapper 以免默认 doctest 引用未启用 API，但双语明确说明：所有 `# ` 隐藏行仅供本库 doctest，消费者应整行省略，不能只移除 `#`。发布给应用的有效主体不得包含本地 digest gate。给完整应用 manifest，明确依赖的 feature 与应用 feature 的区别。

新增一个只在 digest 验证配置下运行的消费者示例集成测试：从明确标记的 Markdown 代码块提取可见主体（删除完整 hidden 行，处理 Rustdoc 的 `##` 转义），生成独立临时 consumer example target；manifest 只启用依赖的 digest，不声明应用级 digest。执行成功和冲突恢复流程，并验证最终磁盘字节和完成 sentinel。可用 `--example` 运行，以使文档的 `tempfile` dev-dependency 生效。生成文件和 target 仅放在测试专属可丢弃目录；与父 Cargo target 分开，避免递归 Cargo 锁等待。不得用复制一份永不校准的业务示例或仅 cargo check 代替执行。

### 9.2 API 可发现性与合同

在 Cargo.toml 增加：

```toml
[package.metadata.docs.rs]
features = ["digest"]
```

不使用 all-features，避免顺带启用 test-support；不改变 default feature，不引入 nightly-only `doc(cfg)`。在入口、writer、提交错误和 recovery 类型的英文 Rustdoc 标明 digest 要求、Reject 策略、允许的模式组合、平台限制、协议不是严格 CAS、commit 消耗 writer、恢复文件所有权和不可盲目重试的状态。复用既有指南链接，增加最小可执行类型级例子。

只补与本轮恢复安全有关的内部不变量：candidate/candidate-copy/recovery entries 的所有权、receipt 含义、何时禁止清理，以及坐标用途；不以统一风格为由逐文件重排或拆类。双语既有设计文档同步记录本轮状态、顺序、路径和期限合同，不额外扩展不在本轮编号中的历史漂移修正。

### 9.3 隔离 doctest

`LocalRenameFailure`／`LocalCopyFailure` 示例使用各自的 `tempfile::tempdir()`，在新目录内选择不存在的 source/target，不能执行全局固定名称上的变更。`LocalFilePermissions` 使用公开路径 `qubit_local_files::outcome::LocalFilePermissions` 并移除 ignore。已指出的 `LocalWriteOutcome` 正常流程也改为临时目录并启用 doctest；不批量移除其他平台受限示例的 ignore。

## 10. xattr 疑点的验证门（RLF-Q01）

位置：`src/local/internal/atomic_metadata/linux_android.rs::get_xattr_inner`。现象假设是第一次长度查询为零、读取前 xattr 增长，第二次 size=0 调用返回新长度，空 Vec 的 truncate 不能产生该内容。当前尚未有原生时序复现。

先在独立临时文件上固定顺序验证：设置空 `user.*` 属性 → 查询零长度 → 更新为非空 → 以零容量缓冲读取，记录返回长度和原生错误。再用仅测试可控边界复现相同序列经过生产读取逻辑；不依赖线程竞速。系统不支持 user xattr 时明确记录验证条件不足，不能当作反证。

若原生语义及生产路径均证实：把 `read > value.len()` 当作 size race，进入与 ERANGE 相同的有界重试；预算耗尽返回错误，禁止返回截断的成功结果。复用现有 `XATTR_SIZE_RACE_ATTEMPTS`，不新增无限重试。验证保持为空、零转非零、非零增长、删除及持续竞争耗尽。

若原生证据否定假设，保留必要的验证证据而不修改生产算法。若本机不能验证且无可用原生环境，状态为“未验证”，在最终实施报告单列，不阻止其他已确认项完成，也不能声称该疑点已修复。

## 11. 验收与风险控制

每个行为修复先有能暴露旧问题的回归，再做最小实现；纯文档/导入修正不编造冗余测试。测试通过公共 API 观察行为，只有 staging 顺序、扫描计数和 xattr 私有边界允许必要的内部测试；不得扩大生产可见性服务测试。

集成只由 T13 汇总执行：默认与全部 feature 的测试、Clippy、Rustdoc、docs.rs 等效 digest 文档、fuzz 编译和下游合同。Linux/Windows/macOS 需要真实运行证据；FreeBSD/Android 保持既有 compile-only 定位。没有平台环境或测试依赖时记录缺口，禁止把静态检查写成实际通过。

最高风险是：副作用合并过度乐观、权限覆盖在 PreserveExisting 后被覆盖、private 路径构造重新引入物理路径授权、清理范围扩大、测试挂钩泄漏到普通构建。每项都有对应验收；任何失败都修在本轮范围，不趁机升级依赖、重写框架或格式化无关文件。

本设计产生的新增选择是实施建议，不是新增用户授权。后续用户明确调整范围时，以后续指令优先更新这两份文档中的范围表。
